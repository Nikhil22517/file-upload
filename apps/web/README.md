# Web app (TanStack Start · shadcn/ui)

The screens for report uploads: upload files, answer the uploads that are held (confirm warnings, pick a report
date or week, set up a template for a report the workspace hasn't seen), browse imported rows and analytics,
and control each report's template.

Everything server-side goes through **TanStack Start server functions** (`src/server/reports.functions.ts`), which
call `@platform/ingestion-service`: the same code the ingestion API runs. Uploads are server functions too
(`FormData`, one request per file, so each file shows its own outcome). The web app needs no API process; the API
stays for Postman, other systems and uploads by URL. Both share Postgres and the upload folder.

## Run

```powershell
pnpm install                                     # from the repo root
cd apps/ingestion-api; docker compose up -d      # Postgres
cd ../web; copy .env.example .env
pnpm dev                                         # http://localhost:3000
```

Production build: `pnpm build`, then `pnpm start` (port from `PORT`, 3001 in `.env.example`).
Everything in Docker, with the API: `docker compose --profile app up -d --build` in `apps/ingestion-api`
(web on :3000, API on :8000).

Migrations run on the first server call (the same idempotent, lock-protected migrator the API runs at startup).

## Screens

| Route | What it does |
|---|---|
| `/` | Pick a workspace, or create one (DSP code + name) |
| `/$workspaceId/reports/daily` · `/weekly` | Daily and Weekly tabs: pick a report, see its latest day (week) or pick a date (Amazon week); jump between periods with data; analytics for that period and searchable rows |
| `/$workspaceId/reports` | Upload (drag and drop, up to 25 files of 25 MB, optional report date and Amazon week); **Needs your attention** list; upload history with filters |
| `/$workspaceId/reports/files/$fileId` | One upload: summary, the action its stage needs (import anyway, set the date or week, teach template, re-import), its analytics, imported rows with unreadable values highlighted |
| `/$workspaceId/reports/templates/new/$fileId` | Set up a report from its first upload: name, header row (tables) or PDF sections, daily or weekly, which columns to keep, each column's type and role, analytics |
| `/$workspaceId/reports/templates` | This workspace's templates (there are no built-in ones) |
| `/$workspaceId/reports/templates/$templateId` | Change a template's controls; its analytics across every upload, recalculated on save |

## Notes

- `src/components/ui` is generated by shadcn (`pnpm dlx shadcn@latest add <component>`; preset `radix-nova`).
- Times render in UTC on the server and switch to the viewer's timezone after load (`LocalTime`), and numbers use
  a fixed locale, so server HTML always matches the first browser render.
- The server build keeps `pdfjs-dist`, `exceljs`, `papaparse`, `pg` and `drizzle-orm` external (see `vite.config.ts`);
  they are dependencies here for that reason.
- **Not done yet:** sign-in and a workspace-membership check in every server function (they are public endpoints
  until then); moving the screens into a module package and `components/ui` into `packages/ui`.
